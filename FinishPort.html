Finish Port: sqlswift Remaining Tasks

A checklist of behaviors, styles, and settings present in the original Go/JS sqldoc that still need to be implemented in the native sqlswift application.

Architecture & Capabilities

  • Web Server / Remote Access: The original Go CLI included a serve command to host databases over localhost via HTTP (enabling Linux/Windows usage and remote access). The Swift port drops this entirely for a pure native macOS approach, permanently losing cross-platform web UI capabilities.

Behavior

  • Full Screen Startup: The original sqldoc (via its Cgo launcher wrapper) explicitly bounds the application window to the user's screen size on launch (fillScreen()). sqlswift uses standard SwiftUI window sizing (.frame(minWidth: 700, minHeight: 450)), which relies on macOS state restoration instead of forcing maximum screen size.
  • Text Selection & Clipboard: VirtualizedGridView currently renders text without textSelection(.enabled) or a custom selection model. Users cannot select, highlight, or copy individual cell values or entire rows to their clipboard.
  • Keyboard Navigation: The virtual grid lacks keyboard event handling for navigating cells via arrow keys, Page Up/Down, Home, or End.
  • Context Menus: Missing right-click contextual menus on rows and cells (e.g., "Copy Value", "Copy Row as JSON", "Export Table").
  • File Pasting: The ability to paste a file path directly into the app to open it (fallback for drag-and-drop).

Style

  • Dynamic Row Heights: Row heights are currently strictly hardcoded to 26 * zoomScale in VirtualizedGridView.swift. Needs to support auto-expanding rows for large text or user-defined resizing.
  • Data Inspector / Detail View: Very long text and BLOB data are truncated (truncationMode(.tail)). There is currently no popover or detail inspector to view the full contents of a truncated cell.
  • Skeleton Loading States: The JS frontend featured skeleton loading rows (.skel) while data was fetching. sqlswift has the design token (DesignTokens.skeleton) but hasn't implemented it in the VirtualizedGridView.
  • Busy / Copy Progress Overlay: The original app had a dedicated, animated #busy overlay for long-running copy/load operations. The Swift app uses a simpler, unstyled ProgressView.
  • Visual Query Timings: StatusBarView reports query duration, but lacks the green (.fast) and orange (.slow) threshold color-coding used in the original app to highlight slow queries.
  • Sidebar vs Picker: The original app used a left sidebar for table navigation. The Swift port uses a titlebar menu picker, which is functional but represents a structural style deviation that might need refinement.

Settings

  • Theme Override: The original app allowed manual toggling between Light and Dark mode (S.doc.style.theme). The Swift app currently inherits the system appearance without offering a manual override setting.
  • State Persistence: Custom column widths (from drag resizing) and other UI states need to be persisted across sessions (similar to the original userSized properties).
